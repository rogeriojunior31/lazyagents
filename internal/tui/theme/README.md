# lazyagents themes

Every theme is a YAML file in the same format as [SP Night](https://github.com/sp-night/sp-night):
a `palette` of named colors and the semantic roles in five groups. UI code never uses hex: it
consumes tokens (`theme.Primary`, `theme.SynString`, `theme.ANSI("red")`) that resolve against
the active theme at render time. That is why package-level styles follow the `theme:` in
`config.yaml`, which `main` applies before the TUI starts.

```yaml
id: my-theme          # optional; if present, it must match the file name
label: My Theme
description: "…"
appearance: dark      # dark | light
extends: sp-night     # user themes only; defaults to sp-night
palette:
  orange: "#f2984a"
ui:
  accent: orange      # "#rrggbb" or a palette name
```

## Where themes come from

- **SP Night** (`sp-night`, `sp-night-garoa`, `sp-night-jaragua`): generated by
  `generate/main.go`, which copies the palette (`palette/sp_night.json`, 23 colors per flavor)
  and the roles (`palette/roles.json`) unchanged. The generator maps the upstream flavors
  (`noite`, `garoa`, `jaragua`) to these ids and sets the English label and description.
  Those upstream names still work as legacy ids in `theme:` and `extends:`. MIT notice in
  [LICENSE-SP-Night](LICENSE-SP-Night).

  ```sh
  go run ./internal/tui/theme/generate -source ~/Projects/SP-Night/sp-night
  go run ./internal/tui/theme/generate -source ~/Projects/SP-Night/sp-night -check
  ```

- **Community** (`tokyonight*`, `dracula`, `gruvbox-dark`, `nord`, `rose-pine*`, `kanagawa`,
  `everforest-dark`, `onedark`): written by hand from each project's official palette (URL in
  the header of each file), with the roles laid out the way the project does it in the editor.
  License notices in [LICENSES-themes.md](LICENSES-themes.md).

- **User**: `<ConfigDir>/themes/<id>.yaml`, loaded by `LoadUser` at boot. A missing role comes
  from `extends`, and `palette` references are resolved after inheritance: changing a named
  color in the child theme repaints every inherited role that uses it.

Every built-in theme must define every role without `extends` and have a contrast of at least
3:1 (WCAG) between the text roles (`ui.fg`, `ui.fg_dim`, `ui.accent`, `ui.accent_alt`,
`diagnostic.*`) and the `ui.bg` and `ui.selection` surfaces; `load_test.go` enforces both. In
the community themes, when the original assignment fails, the role uses another color from
the same palette; if none passes, a derived color goes into the `palette` with the comment
`# outside the official palette: contrast` (today in Nord, Dracula and Rosé Pine Dawn).

## Roles and tokens

| Group | Roles | Tokens (what they paint in the TUI) |
| --- | --- | --- |
| `ui` | `bg`, `bg_deep`, `panel`, `float`, `line`, `selection` | `Bg` background, `Deep` text of the active tab pill, `Surface` cards, `Float`, `Line`, `Sel` selected row |
| `ui` | `border`, `border_active` | `Border`, `BorderFocus` |
| `ui` | `fg_bright`, `fg`, `fg_dim`, `fg_muted` | `Bright` titles, `Text`, `Subtle` hints and labels, `Muted` |
| `ui` | `accent`, `accent_alt`, `cursor`, `link`, `match`, `on_accent` | `Primary` identity (active tab, Claude Code), `Accent` secondary (Gemini CLI), `Cursor`, `Link`, `Match`, `OnAccent` |
| `diagnostic` | `error`, `warn`, `info`, `hint`, `ok` | `Err`, `Warn`, `Info`, `Hint`, `OK` (toasts, states, OpenCode) |
| `git` | `added`, `modified`, `removed`, `renamed`, `staged`, `untracked`, `conflict` | `Added`/`Removed` in the skill profile diff, and the rest |
| `syntax` | `keyword`, `function`, `type`, `string`, `number`, `constant`, `comment`, `tag`, `punctuation` and 17 more | `SynString` code in markdown, `SynPunct` fences, `SynComment` quotes and frontmatter, `SynKeyword`… |
| `ansi` | `black` … `bright_white` (16) | `ANSI(name)`, colors of agents without their own color |

Plugins receive in `init` the `theme.colors` map with every token and every role
(`ui.accent`, `ansi.red`…) in hex.

`Paint` reapplies a surface's colors after every ANSI reset inside it (`\e[m`, `\e[39m`,
`\e[49m`), so nested spans do not punch holes in a card's background.
